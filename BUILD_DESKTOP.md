# Building the SuperNova AI Windows Desktop App

Your project is a **React (Vite) frontend + FastAPI (Python) backend**. To turn
it into a desktop/Windows app, the backend now also *serves* the built frontend,
and a small launcher (`launcher.py`) opens it in a **native window** using
[pywebview](https://pywebview.flowrl.com/). No browser, no separate servers — it
looks and feels like a normal Windows program.

You have **two ways** to deliver it. Pick based on what your mentors need.

---

## Option A — One-command run (REAL models) ✅ recommended for the demo

Best when your mentors have (or can install) Python and you want the **real
trained models** (torch ensemble) running.

1. Make sure **Python 3.11+** and **Node.js 18+** are installed.
2. Double-click **`run_desktop.bat`** (or run it in a terminal).

The first run creates a virtual environment and installs everything (including
torch — this downloads a few GB and takes a while). Every run after that is
instant. The app opens in its own window.

> The real model weights are read from `models/weights/`. They're already in your
> project, so real inference works out of the box.

---

## Option B — Standalone `.exe` (no Python needed) 

Best when you must hand mentors a **self-contained app** they can just run.

1. Make sure **Python 3.11+** and **Node.js 18+** are installed *on your build
   machine* (mentors won't need them).
2. Double-click **`build_windows.bat`**.
3. When it finishes, your app is at:

   ```
   dist\SuperNovaAI\SuperNovaAI.exe
   ```

4. **Zip the entire `dist\SuperNovaAI\` folder** and submit that. Mentors unzip
   and double-click `SuperNovaAI.exe`.

### Important trade-off for Option B
The standalone `.exe` is built **without** the heavy deep-learning stack
(torch / opencv / segmentation-models), so it stays small (~tens of MB) and
reliable. With those excluded, inference uses the built-in **mock** fallback —
the full app (login, upload, review, annotate, finalize, export) works
identically, but the lesion mask/heatmap are generated by the placeholder, not
the trained models.

**If you need the real models inside the `.exe`:** before building, remove the
`excludes=[...]` line in `supernova.spec`, install torch into the build venv,
and copy `models\weights\` next to the final `.exe`. Expect a 1–3 GB output and
a slower build. For a graded demo, Option A is the simpler way to show real
model output.

## What changed to make this work

- `frontend` is rebuilt with `VITE_API_BASE_URL=/api` so the UI calls the
  backend on whatever port it's running — no hardcoded `localhost:8000`.
- `backend/app/main.py` already serves `frontend/dist` (SPA) alongside `/api`.
- `backend/app/ml/inference.py` now reads weights from `SUPERNOVA_WEIGHTS_DIR`
  when set, so the packaged app can find them next to the executable.
- `launcher.py` starts the backend on a free local port and opens the native
  window.

## Troubleshooting

- **Window is blank / "can't reach page":** the backend needs a second to start.
  If it persists, run `python launcher.py` from a terminal to see errors. To see
  logs from the `.exe`, set `console=True` in `supernova.spec` and rebuild.
- **WebView2 missing (older Windows 10):** install the free Microsoft
  "Evergreen WebView2 Runtime". Windows 11 already has it.
- **`npm` or `python` not found:** install Node.js / Python and make sure they're
  on your PATH, then retry.
